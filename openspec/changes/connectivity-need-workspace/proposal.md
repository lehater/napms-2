# REAL-потребность от реестра до заявки

## Why

Потребность объясняет, зачем процессу нужна коммуникация. Сейчас для поиска записи нужно знать процесс, а при создании интерфейс просит выбрать конкретную сетевую ревизию. В процессе с несколькими версиями одной коммуникации этот выбор не соответствует идентичности сохраняемого объекта.

## What Changes

- Дать пользователю общий реестр и сохранить вход из процесса в ту же карточку.
- Вынести создание потребности в форму выбора процесса и направленного взаимодействия с businessBasis.
- Оставить в карточке предметные сведения, коммуникацию и историю. По действию из карточки открывать композицию заявки с выбором точной ревизии и развёртываний.

## Capabilities

### New Capabilities

- `connectivity-needs` — дополнительные требования к REAL-представлению и выбору взаимодействия. Путь продолжает одноимённые дельты `persist-connectivity-need` и `business-connectivity-lifecycle`, пока не архивированные в основной каталог спецификаций.

## Impact

#140 передаёт дизайн и аудит для #141–#143. Реализация затронет REAL Sidebar, списки и карточки, типизированный клиент и FastAPI-проекции поверх текущей SQLite. Сквозная проверка использует существующий сценарий Request → Decision → Rule. Предметные решения D-04/D-06, существующие идентификаторы, история и полномочия остаются контрактами совместимости.
