# Context growth and relevance — research direction

Status: proposed research priority following owner question 2026-11-22. No Harness/config change, new telemetry read, experiment execution or new Issue authorized by this note. Two distinct capabilities: F18 quantitative context composition/growth attribution; F19 qualitative context relevance and behavioral effect. F19 follows F18, with F07 outcome anchor.

## Existing evidence and source boundary

The [historical HE register](https://github.com/lehater/napms-2/blob/ca179deeb523acf6c5e430db8873ebedfecf4c65/docs/engineering/harness-efficiency-register.md) reports one call's context increasing about 17.5k to 164.8k and another execution 19,375 to 94,565 tokens; separate tasks inherited large history. These are prior reports, not new measurements or proof of irrelevant content. HE-004/011 session routing was addressed in #145/PR #148; effect unknown. HE-002 is a distinct exporter representation defect: [Langfuse #20582](https://github.com/langfuse/langfuse/issues/20582) reports duplicated base instructions in reconstructed input, but one copy in the captured native request and matching usage. Do not infer inflated billing or actual duplication from reconstructed text.

Distinguish cumulative input usage, input per inference, active context estimate, bytes of persisted transcript, and cached input. Cumulative usage grows by processing retained context again; cache status is not semantic relevance. See [OpenAI Codex agent loop](https://openai.com/index/unrolling-the-codex-agent-loop/), [token accounting](https://github.com/openai/symphony/blob/main/elixir/docs/token_accounting.md). Current upstream implementation may differ from installed versions.

Preferred source for F18: [native rollout trace, Codex rust-v0.171.0](https://github.com/openai/codex/blob/rust-v0.171.0/codex-rs/rollout-trace/README.md). The reduced graph separates model-visible conversation items from nested runtime tools and terminal outputs. Prepared prompt references include ordered history, instruction provenance and tools; transmitted request may be incremental with previous_response_id. Same recording binary must reduce bundles. Raw payloads can be partial/truncated; encrypted reasoning/compaction and hidden server context cannot be assigned exact semantic categories. Ordinary session JSONL may support a lower-confidence structural analysis; never sum log copies or replacement histories into active context. Langfuse supplies usage/coverage and aggregate candidates, not authoritative exact input composition. Prior F03 historical S2 inputs unavailable; do not broadly search or reconstruct them.

## F18 — quantitative composition

Input: one naturally occurring, completed, bounded task in one identified session/thread, ideally existing intact native bundle with exact recording executable. Otherwise use a separately approved native trace for the next ordinary task, not an artificial workload. First check retained known material and available native readers; no new generic parser, network read, persistent configuration, or raw prompt printing by an agent.

Output: start/mid/peak/end observed inference context measures; top growth intervals (within a thread and compaction segment); approximate composition by mutually exclusive primary origin (base and developer/project instructions, user/handoff, tool declarations, assistant messages/call arguments, model-visible tool results, opaque reasoning/summary and unknown). For tool results use secondary source labels such as code, instructions/skills, CI/logs/tests, API/telemetry, other/unknown where evidence permits. Measure bytes or characters explicitly as such; token counts only using validated accounting/tokenizer with coverage/residual, not byte estimates presented as actual usage. Distinguish repeated retained content across calls from repeated injection into one active prompt, inherited history, compaction replacement and independent subagent contexts. Top increases may contain multiple items. Compare pre/post compaction only against the observed replacement. No arbitrary text in published output; raw evidence stays in approved local runtime. No self-ingesting trace content in model-visible tool output.

## F19 — relevance and degradation

Input: F18 largest contributing segments, original task criteria and contemporaneous subsequent decisions/outcome. Review a bounded sample against task needs: required, useful, incidental/obsolete, duplicate, unrelated subtask, or unknown; use separate labels for origin and relevance. A long log, failure diagnosis, repeated read, or a cached item is not automatically waste. Distinguish a necessary recovery from avoidable auxiliary work, and active unnecessary context from work whose result is only persisted externally. Check observable deviations (forgotten constraint, unjustified action, extra retry/rework) against F04/F07/F17 evidence. Initial retrospective association is not causality. If a concrete removable source is supported, separately propose a matched outcome comparison changing only its inclusion, evaluating quality, steps, context and cost. Do not reduce context blindly.

Research leads: [Lost in the Middle](https://arxiv.org/abs/2307.03172), [Chroma Context Rot](https://www.trychroma.com/research/context-rot), [Diagnosing and Mitigating Context Rot in Long-horizon Search](https://arxiv.org/abs/2606.29718); counterpoint [How Fast Do Agents Rot?](https://arxiv.org/abs/2609.01660) reports step count rather than context length explaining degradation in its controlled tasks. User's hypothesis is plausible, not established for NAPMS. Public [Codex #52942](https://github.com/openai/codex/issues/52942) is a related user report of context growth, not proof of the same defect.

Next: F18 native source feasibility and minimal one-session measurement, then decide whether F19 is possible. Prioritize research ahead of unstarted methods; no automatic interventions or new infrastructure.
