## Shared Langfuse access decision (2026-11-22)

The owner designates the existing local `~/.codex/langfuse.json` as the trusted source of Langfuse connection parameters in the execution VM. Use its explicit base URL and existing keys with the installed official CLI and Skill. Load values without displaying them in the same shell invocation as the query; do not rely on inherited variables or default Cloud endpoints. Do not duplicate the endpoint or credentials in the repository, prompts or other configuration. No per-task endpoint confirmation is required for the owner-maintained configuration. If it is missing, invalid, or access fails, report the blocker; do not discover alternative hosts or modify connection settings. Task authorization still specifies the permitted telemetry scope and read-only operations; this decision does not confer write permission or establish technical restrictions on the key. This common connection rule supersedes the per-handoff endpoint-confirmation requirement in historical experimental plans for future authorized runs. Historical reports/plans remain intact. This rule is now canonical in [the accepted read-access procedure](https://github.com/lehater/napms-2/blob/b21fd63234cce8e1d91f0af1dcf3718cf7033944/.ai/langfuse-read-access.md) (PR #172 merged, Issue #171 completed). Refer to that procedure for future tasks rather than duplicating connection instructions. Record safe stage-specific pipeline exit codes on failures; never expose raw stderr or response payloads. Global files remain unchanged.
