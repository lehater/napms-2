# F03 — run-001: phase-flow method and reusable parser feasibility

Status: PARTIAL — published method and reusable action parser inspected; no local phase sequence or new behavioral finding established. Coordinator-only research and static inspection; no executor invocation, telemetry query, installation or third-party code execution.

## Source and selected method

- [Graphectory / Langutory, OOPSLA 2026](https://arxiv.org/html/2512.02393v2), §§2.1, 2.3.1, 3.3: phase-label actions by a consensus map and relevant context (e.g. test target and earlier patching); compress consecutive equal labels into phase skeleton and run lengths; analyze transitions. The paper's 4,000 trajectories are SWE-agent and OpenHands. The reported intervention benefit is not an isolated effect of phase labeling.
- [AgentLens](https://arxiv.org/abs/2605.12925): distinguishes action intent using trajectory history; its abstract describes exploration, implementation, verification and orchestration. Full text unavailable in this retrieval, no independent effect claim.
- [Badertdinov and Golubev, Interpreting Coding Agents Through Their Behavioral Trajectories, 2026-11-12](https://arxiv.org/html/2611.17440v1), §§3.1–3.3, 4.1 and appendix A: 143,209 trajectories, 125 configurations; 82.4% primary-operation agreement with a six-model consensus reference (500 stratified actions; 5/6 required). This includes Codex in the corpus but is action classification, not intent/phase inference; no human ground truth or local validation. [Released parser](https://github.com/SWE-rebench/trajectory-analyzer/tree/ee056f18d778ab3f0c664a65db64b292fe7edf5d), MIT, standard library Python 3.10+. README discloses missing original datasets and changed parser relative to research version; normalized file_change events are unsupported and affected results partial.

Select Langutory phase skeleton as the downstream representation; treat the new parser as a candidate upstream action classifier, not a solution to phase classification.

## Compatibility boundary

Static inspection of [parser.py at the pinned commit](https://github.com/SWE-rebench/trajectory-analyzer/blob/ee056f18d778ab3f0c664a65db64b292fe7edf5d/parser.py) via GitHub:

- CLI accepts messages, evaluated-final, normalized-events JSON schemas; no direct native Codex JSONL or Langfuse Observations API input advertised.
- Core expects action messages, tool calls with function name/arguments, and observation messages; pairing requires consistent IDs, with response/parent fallbacks. CWD and trusted repository root matter for path-role inference.
- Parser recognizes compound shell operations and emits uncertainty/coverage diagnostics. It can also emit raw canonical command signatures and unmatched command names, so output must remain local until allowlisted. It is not a drop-in safe telemetry reader. Do not execute third-party code with secrets or unrestricted access without separate review.
- Our [F02 run-002](../F02-pattern-detection/run-002.md) already paired 35/35 wrapper calls and linked 36/36 command events in S2/#151; 22/36 command categories remained unknown. [F02 run-006](../F02-pattern-detection/run-006.md) found unresolved Langfuse input shapes. The public parser expects normalized action/output inputs; no direct compatibility or improvement in coverage has been established.

## Decision

Reuse an existing classifier if a narrowly bounded adapter is feasible, and validate a small semantic sample before computing phase transitions. Do not start custom generic parser work or install new infrastructure.

No raw input/output/path/IDs, no external code execution or network telemetry request. If those inputs are not available with minimal extraction, park F03 and continue F07.
