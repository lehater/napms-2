# F16 — Deterministic offloading / pilot v0.1

Coordinator-selected after F02 run-001 and run-002. This is a narrow engineering adaptation, not a reproduction of [TraceCompiler](https://arxiv.org/html/2608.02680v1) (sections 3.3–3.5) or [FlashScript](https://arxiv.org/abs/2610.33876). TraceCompiler classifies input provenance and verifies dependencies rather than assuming chronological adjacency; FlashScript separates deterministic operations from judgment. TraceCompiler does not establish net efficiency including compilation cost. FlashScript results concern other tasks/models. No local effect is assumed.

## Hypothesis and scope
The completed F02 suboperation that pairs tool calls and outputs using exact call IDs is a deterministic offloading candidate. F02 reports already show successful pairing (S2 35/35, S3 59/59); they do not prove repeatable runtime equivalence or savings. The unsuccessful classification of shell command semantics is outside scope. The experiment tests the candidate and the evidence for its separation, not discovery across a large corpus. No new permanent script or Harness change.

## Coordinator's initial analysis
Inputs: authorized local JSONL file with structured call/output records, existing schema and identity crosswalk. Binding types: known file input, fixed schema fields, copied call IDs, deterministic exact equality/grouping and counts. Outcome: pair mapping and unmatched/ambiguous counts. Semantic reasoning is needed only if schema/identity is unsupported, not to pair known IDs. Unknown/missing or duplicated IDs must remain unmatched/ambiguous rather than guessed. Side effects: none. Candidate reuse: the already existing temporary F02 extraction script if its pairing stage is independently callable/read-only. Native alternatives have not yet been compared. Baseline elapsed time is for combined stages, not pairing alone; do not calculate savings from it.

If outputs are not available to compare, mark unknown. Existing report is a consistency reference, not independently annotated ground truth. Report whether validation of duplicate/missing IDs exists in existing script only if directly visible; do not modify or add tests. A mismatch is a result, not a reason for repairs.

Acceptance: a concrete candidate with evidence of deterministic boundary and executable reuse/consistency, or exact blocker.
