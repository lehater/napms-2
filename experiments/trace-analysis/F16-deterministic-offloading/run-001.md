## Candidate and separability

The candidate is the F02 suboperation that maps wrapper calls to outputs by exact call ID. Its intended inputs are the existing S2/S3 structured records; its outputs are call/output pairings and unmatched or ambiguous counts. The temporary F02 script `f02_run002.py` contains this logic inline in `extract()`. That function also parses nested commands, links execution events, classifies actions and read ranges, computes F02 pattern results, and persists a local summary. The script exposes no pairing-only entry point or function. Running it unchanged would therefore execute the broader classification, contrary to this pilot's scope. No script or trace was modified.

The inspected pairing block builds an output lookup by call ID, treats repeated output IDs as ambiguous, and counts absent IDs or outputs as unpaired. It does not visibly validate duplicate call IDs before looking up outputs; one-to-one uniqueness is therefore not established by that code alone. The inspected path uses local inputs and local summary persistence; no network or LLM call was identified. No native pairing alternative is documented in the existing F02 materials; they state that native alternatives had not yet been compared.
