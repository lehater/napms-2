# Local multi-agent SDLC — проектирование

**Статус:** архитектурное предложение (не принято владельцем, не внедрено).
**Дата:** 2026-11-14.
**Базовый `main`:** `688cbce28ffa5c75edc85a65465797083f68366a`.
**Ветка:** `research/local-multiagent-sdlc`.
**Область:** SDLC/Harness NAPMS 2.0, без изменений кода продукта, действующего Harness, OpenSpec и CI.

## Цель

Разработать *полную* целевую архитектуру локальной разработки с разделёнными ролями, контекстами и переключаемыми моделями/провайдерами. Внешний ChatGPT не должен быть обязательным координатором каждого изменения. GitHub `main` остаётся источником принятых решений; владелец утверждает продуктовые и архитектурные развилки, приёмку и merge.

## Предлагаемое решение (ожидает ревью)

- **Приоритетный кандидат для локальной проверки:** OpenCode V2: роли с собственными моделями/полномочиями, запуск локально, поддержка существующих `AGENTS.md` и `.agents/skills/`. Окончательный выбор — только после сравнения с работающим Codex.
- **Базовая система и резерв:** установленный Codex CLI с поддерживаемыми проектными субагентами. Он уже подтверждён в PR #60; миграция не должна разрушить рабочий путь.
- **Оркестрация:** режим A — локальный Orchestrator выполняет принятый план без нового промпта в активной сессии; режим B — **условный** детерминированный Controller выполняет DAG с checkpoint/restart при подтверждённой необходимости. Explorer, Architect, Planner, Worker, Reviewer — LLM-специалисты; Validator — без LLM. Контракт описан в ADR-002.
- **Режимы моделей:** сильный / стандартный / экономичный / локальный; назначение по сложности, критичности и доступности. Без выдумывания API для чтения лимитов.
- **Принцип:** сначала описать *весь* целевой дизайн; затем внедрять через проверяемые изменения с возможностью отката.

**Одна непрерывная работа** означает последовательное выполнение разрешённых задач, а не бесконтрольное отсутствие остановок: при owner gate, P0 и исчерпании бюджета требуется остановка. Безопасный unattended restart не обещается режимом A и требует режима B.

Это архитектурный выбор на основании документации, **не доказательство**, что OpenCode уже установлен или авторизован в пользовательской WSL. До изменения текущего Harness обязательна короткая локальная проверка модели, доступа, навыков, прав и запретов.

## Управление изменениями

Оставлять ветку и PR в Draft до принятия владельцем. Не менять `main`, PR #66/#67, CI, код продукта, IAM, локальные учётные данные и токены. Не утверждать полноту проверок при отсутствии фактического запуска.
