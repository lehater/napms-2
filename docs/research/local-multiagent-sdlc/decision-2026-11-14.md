# Decision record — staged OpenCode adoption after PR #69

**Date:** 2026-11-14.
**Decision scope:** по поручению владельца продолжить следующий этап после успешного squash merge [PR #69](https://github.com/lehater/napms-2/pull/69) в `main@ab62ca13bb15a9f5dd26f2dca5dbef54d92bb8d0`.
**Статус:** ADR-001 accepted **для staged implementation OpenCode V2 (mode A)**; ADR-002 mode A accepted **для внедрения**; mode B remains Proposed / Deferred. Это решение **не является** согласием на merge PR #68 или следующих implementation PR без отдельного подтверждения.

## 1. Фактические входы

- **Работающая среда:** WSL2 Ubuntu 24.04, OpenCode `v2.2.0`, Ollama `qwen3-coder:30b`, OpenSpec Skills и `AGENTS.md`, без добавленных платных API.
- **Подтверждённый E2E smoke:** в [merged PR #69](https://github.com/lehater/napms-2/pull/69) пять агентных ролей Explorer → Planner → Worker → Validator → Reviewer прошли в одном root session, с независимым Reviewer и ограниченным bwrap Worker. Пилот использовал **только локальную Qwen** для каждой роли.
- **Проверка CI:** [GitHub Verify FULL run #43563373955](https://github.com/lehater/napms-2/actions/runs/43563373955), `success` на точном head `4274bbad545ad871ac69297d7e1d67241b937867`; после этого merged squash commit `ab62ca13bb15a9f5dd26f2dca5dbef54d92bb8d0`. При новых кодовых изменениях требуется новая проверка.
- **Облачная модель:** `openai/gpt-6.1-sol` успешно ответила на отдельный реальный запрос через ChatGPT в WSL. Во время пилота один запрос возвращал 503; после этого пользователь повторил запрос и получил `OK`. В пяти агентных ролях модель **не использовалась**. Надёжность/стоимость/качество на рабочем scenario неизвестны.

## 2. Принятые решения

| ID | Решение | Обязательная граница |
| --- | --- | --- |
| D1 / ADR-001 | **OpenCode V2** — основной путь для первого внедрения постоянного мультиагентного Harness | До успешного ограниченного продуктового E2E **Codex CLI остаётся рабочим основным baseline** и fallback |
| D2 / ADR-002 | **Режим A:** A1 — одна физическая root-сессия; A2 — один логический run из раздельных авторизованной read-only и credential-free worker-сред; ручной handoff до подтверждения автоматизации | Не обещать общей физической сессии в A2, restart-safe exactly-once или unattended DAG |
| D3 | **Режим B (deterministic Controller)** остаётся deferred | Не добавлять контроллер до отдельного одобрения необходимости восстановления после прерывания |
| D4 | OpenSpec/GitHub/Verify — источник истины; Reviewer не меняет код; Validator проверяет реально | Нет фиктивных PASS, одноразовый bwrap smoke не равен production sandbox |
| D5 | Выбор моделей выполняется по реальной доступности и измеренному результату | `gpt-6.1-sol` — кандидат на задачи высокого риска, `qwen3-coder:30b` — подтверждён для pilot, но их эффективность в ролях ещё не сравнивалась |
| D6 | **Implementation A4–A7** вести в новой ветке и **Draft PR**, сохранив текущие Codex config/AGENTS/OpenSpec | Никакого автоматического merge, изменения IAM, секретов, платных обязательств или неограниченного shell |

## 3. Входы / выходы первого implementation slice

**Вход:** `main@ab62ca1`, merged `pilot/opencode.jsonc` как reference, контракт ролей в [target-architecture.md](target-architecture.md), проверенные права из evidence #69.

**Ответственность:** минимальный реиспользуемый OpenCode V2 role catalog, разграничение Orchestrator / Explorer / Planner / Worker / Validator / Reviewer, независимый review, профили моделей; минимум кастомных агентов и зависимостей.

**Выход:** отдельный Draft PR с универсальной (не связанной с `pilot/output.md`) конфигурацией; явный запуск из WSL; read-only проверка; один безопасный, ограниченный write/validator/reviewer smoke в disposable worktree; доказательства actual tools/model/exit codes/HEAD. Только после этого допуск к реальной bounded product задаче.

**P0 ограничения:** запрещены автономное изменение `main`, merge, изменение другого PR, доступ к токенам и несанкционированная запись. Не переносить `pilot/README.md` как production runbook без проверки и не включать full-shell Allow на Worker.

## 4. Следующие проверяемые gates

1. На актуальной `main` создать отдельную implementation ветку. В PR #68 сохранить архитектуру, не смешивать с runtime-кодом.
2. Настроить минимальный generic role catalog, проверки схемы V2 и read-only запуск; проверка bwrap/permissions — обязательно в реальной WSL перед Ready.
3. Выбрать модель для Orchestrator/Architect/Reviewer после реального сравнения Sol и Qwen на одной bounded задаче. 503 может повторяться — fallback, а не фиктивный PASS.
4. Проверить текущий `Verify` (ручной `workflow_dispatch` в `main`); запустить FULL на final candidate, независимо проверить и запросить owner acceptance.
5. Отдельно решать о merge PR #68 и implementation PR; решение D1–D6 **не подменяет GitHub merge gate**.
