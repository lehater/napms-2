# Основная навигация перед продуктовой приёмкой

Решение владельца для PR #55 заменило общую семиколлекционную навигацию UI/IA Baseline v0.2 на рабочую навигацию. Issue #64 добавил группу каталогов приложений и развёртываний; change `real-resource-endpoint-catalog` добавляет Resource. Текущий REAL Sidebar содержит:

| Группа | Пункт | Маршрут |
| --- | --- | --- |
| Бизнес-контекст | Бизнес-процессы | `/business-processes` |
| Каталоги | Ресурсы | `/resources` |
| Каталоги | Профили приложений | `/applications` |
| Каталоги | Развёрнутые компоненты | `/deployments` |
| Управление доступом | Заявки на доступ | `/access-requests` |
| Управление доступом | Правила политики | `/policy-rules` |

Потребности открываются через вкладку соответствующего процесса. Выбор Need отображает его как выбранный и открывает композицию заявки. Смена страницы списка или обновление очищает выбор и подтверждение. Полный состав заявки показан перед отправкой.

Правило политики — отдельная REAL-карточка `/policy-rules/{ruleId}`, доступная по серверной ссылке из ALLOWED заявки. Коллекция `/policy-rules` показывает доступные канонические ACTIVE/INACTIVE правила, подписи и трафик. Доступ требует `policy.export` на оба ресурса. Выгрузка доступной текущей политики содержит только авторизованные ACTIVE правила; глобальная полнота не заявляется. На карточке сохранены Rule ID при смене actor, breadcrumbs и возврат к коллекции правил, включая состояние 403 для Decider до переключения на Exporter.

Пункт «Ресурсы» ведёт к коллекции, созданию и деталям Resource/Endpoint с реальными связанными Deployments. Пункт «Профили приложений» ведёт к Application/Component/Interaction, а «Развёрнутые компоненты» — к ComponentDeployment и связанным Resource. Sidebar не показывает неработающие коллекции, учебные ссылки или отдельные метки REAL/MOCK. Сохранены группировка, активный пункт (включая контекст Rule в управлении доступом), контраст, изменение ширины 200–360 px, клавиатура/указатель и мобильная компоновка. Прежний ключ предпочтения ширины сохранён для совместимости.

Исторический прототип доступен **только по прямым** `/prototype/*` URL для исследования и регрессионных тестов. Его семь коллекций, fixture и SimulationProvider подключаются лениво внутри этой ветки маршрутов. Его Sidebar ведёт только в `/prototype/*`. Общими с рабочим приложением являются представление каркаса, resize и стили; рабочий Shell не читает Simulation и не импортирует mock data. Авторизация, серверные операции и поведение при ошибках не изменены.

Семантика исторического fixture и шесть рабочих пунктов отдельно зафиксированы в [JSON-контракте](../contracts/ux-0-semantic-boundaries.json). Проверки семи пунктов относятся к прототипу, шести — к рабочему UI. Исторические документы и материалы сохраняются; требования каталогов описаны в OpenSpec changes `real-application-deployment-catalogs` и `real-resource-endpoint-catalog`.
