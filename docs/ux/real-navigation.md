# Основная навигация перед продуктовой приёмкой

Решение владельца для PR #55 заменяет общую семиколлекционную навигацию UI/IA Baseline v0.2 на рабочую навигацию:

| Группа | Пункт | Маршрут |
| --- | --- | --- |
| Бизнес-контекст | Бизнес-процессы | `/business-processes` |
| Управление доступом | Заявки на доступ | `/access-requests` |

Потребности открываются через вкладку соответствующего процесса. Выбор Need отображает его как выбранный и открывает композицию заявки. Смена страницы списка или обновление очищает выбор и подтверждение. Полный состав заявки показан перед отправкой.

Правило политики — отдельная REAL-карточка `/policy-rules/{ruleId}`, доступная по серверной ссылке из ALLOWED заявки. Общего списка правил нет. На карточке сохранены Rule ID при смене actor, breadcrumbs и возврат к реальным заявкам, включая состояние 403 для Decider до переключения на Exporter.

В основном Sidebar нет Каталогов, неработающих коллекций, учебных ссылок или отдельных меток REAL/MOCK. Сохранены группировка, активный пункт (включая контекст Rule в управлении доступом), контраст, изменение ширины 200–360 px, клавиатура/указатель и мобильная компоновка. Прежний ключ предпочтения ширины сохранён для совместимости.

Исторический прототип доступен **только по прямым** `/prototype/*` URL для исследования и регрессионных тестов. Его семь коллекций, fixture и SimulationProvider подключаются лениво внутри этой ветки маршрутов. Его Sidebar ведёт только в `/prototype/*`. Общими с рабочим приложением являются представление каркаса, resize и стили; рабочий Shell не читает Simulation и не импортирует mock data. Авторизация, серверные операции и поведение при ошибках не изменены.

Семантика исторического fixture и два рабочих пункта отдельно зафиксированы в [JSON-контракте](../contracts/ux-0-semantic-boundaries.json). Проверки семи пунктов относятся к прототипу, двух — к рабочему UI. Исторические документы и материалы сохраняются; требования новых каталогов не реализуются этой очисткой.
